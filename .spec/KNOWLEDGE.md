# KNOWLEDGE

## 現在の設計判断

- CommandSetが許可済み候補を定義順に評価し、入力全体を解決する。Matcherが入力本文の解釈とwildcard抽出を担当し、Runnerが実行設定とwildcard展開を所有する。
- 単一コマンドは複数行入力を扱うが、複数行チェーンは全体を拒否する。interaction = "command" の親コマンドと明示的な返信コマンドはチェーン不可とする。
- パースエラーは入力全体を停止し、先頭がマッチ済みならその出力先へ通知する。チェーン途中の未マッチコマンドとargv生成失敗は終了コード127として処理し、別の候補を選び直さない。
- 設定の既定値・継承・検証はmainのresolveConfigで一度だけ解決する。Raw設定は未指定値を保持し、runtimeのCommandはMatcher・Runnerの設定を重複保持しない。--check-configはRunnerを生成しない。
- Commandの出力先と返信用CommandSetは構築時に渡す。runtimeのCommandSet・Matcher・Runner・Executorは複数workerと非同期HTTP実行で共有する。
- Dispatcherはexec/composeを含む入力をqueueへ、HTTPだけの入力を非同期Executorへ、stdin返信をRunnerへ直接渡す。queueと非同期実行は同じConversationLocksを使い、会話ごとの実行を直列化する。待機順は厳密なFIFOではない。
- DispatcherのCloseと非同期WaitGroupへのAddは同じmutexで保護する。listener終了後にCloseし、workerと非同期実行の完了後に出力queueを閉じる。WaitはClose後に呼ぶ。
- ConversationIDは会話の識別子で、Slackではchannel IDとroot timestampの組に対応する。Slack固有のmention・quote・entity・URL表現はpubsubで正規化する。
- ConversationRouterはroot/replyのroutingと明示的な返信先のcacheを所有する。cacheは未確認・返信先なし・返信先ありを区別し、live受付とhistory復元で同じ実行可否判定を使う。cache miss時はRootInputResolverから起点本文と起点senderの候補indexを取得する。
- StdinStoreは実行中のendpointと暗黙の返信Commandを一括管理する。Runnerの開始後に登録し、古いendpointの終了では新しい登録を消さない。チェーン内では実行中の各Commandがstdinを所有する（[active stdin reply ACL](../docs/decisions/2026-10-03-active-stdin-reply-acl.md)）。
- RouterはACL判定時のendpointを入力に保持し、stdin reply RunnerはStoreを再検索せずそのendpointだけへ全文を渡す。終了・満杯で配送できない返信を別コマンドとして再解釈しない。
- Slack ACLはglobal command index付きListenerConfigへ解決する。トップレベルallowlistが最大範囲で、下位の非空リストは親の部分集合、空リストは継承する。root候補とreply候補を分け、stdin返信は親の解決済みACLを引き継ぐ（[command ACL](../docs/decisions/2026-10-01-command-acl.md)）。
- accept_reminderはcommand/reply専用で継承しない。Reminderはuser allowlistを免除しchannel allowlistを適用する。通常のbot投稿はBot IDで判定し、自身の投稿は除外する。
- timeoutは各Commandのcontextと表示をExecutorで管理する。専用のWithTimeoutCauseにより、親contextのcancel/deadlineや通常の143終了とCommand自身のtimeoutを区別する。Runnerは終了コードだけを返す。
- stdin_idle_timeoutはprocess timeoutと独立したEOFの安全弁で、0は無効とする。interactive stdinはexec/composeで使い、HTTPには適用しない。durationの指定規則は[duration settings](../docs/decisions/2026-10-04-duration-settings.md)を参照する。
- CommandOutputは出力の抽象境界で、pubsubのSlackOutputが非公開queueと単一writerを所有する。各Commandの表示設定・flush intervalを適用し、最後のFlushと全producerの終了後にqueueを閉じる。parse errorはStart/Finishを発行せずsystem出力として送る。

## 既知の境界上の課題

- RootInputResolverはcmd側からtransport側へ問い合わせる境界を持つ。Slack実装は同期的に履歴を取得する。
- runWithLifecycleInputの引数はstdin lifecycleの追加に伴い増えている。独立helperの範囲は、実行contextを持つrunMatchedCommandとの責務分担と併せて見直す余地がある。
